# Book of Leviticus

*Rust topic: Structs, Enums, Pattern Matching, and Methods*

## Chapter 1: Structs and Their Fields

1 A struct is a custom data type that groups related values into named fields:
   ```rust
   struct User {
       name: String,
       age: u32,
       active: bool,
   }
   ```

2 Create an instance by specifying values for each field:
   ```rust
   let user1 = User {
       name: String::from("Alice"),
       age: 30,
       active: true,
   };
   ```

3 Access fields with dot notation:
   ```rust
   println!("{}", user1.name);
   println!("{}", user1.age);
   ```

4 A mutable struct instance allows changing field values:
   ```rust
   let mut user2 = User {
       name: String::from("Bob"),
       age: 25,
       active: true,
   };
   user2.age = 26;
   ```

5 The field init shorthand lets you use variable names as field names when they match:
   ```rust
   let name = String::from("Carol");
   let age = 28;
   let user3 = User { name, age, active: true };
   ```

6 The struct update syntax creates a new instance using fields from another:
   ```rust
   let user4 = User {
       name: String::from("Dave"),
       ..user3 // uses remaining fields from user3
   };
   ```

7 Tuple structs are structs without named fields. They are useful for creating new types:
   ```rust
   struct Point(i32, i32);
   struct Millimeters(u64);
   ```

8 Unit-like structs have no fields and are useful when you need a type to implement a trait:
   ```rust
   struct AlwaysEqual;
   ```

9 Rust does not have inheritance. Structs are composed, not inherited. Use composition and traits instead.

10 Ownership rules apply to structs: if a struct contains a non-`Copy` type like `String`, the struct itself is moved on assignment.

11 Data can be stored on the stack (for `Copy` types) or the heap (for types that allocate, like `String` and `Vec`).

## Chapter 2: Methods and Impl Blocks

1 Methods are functions defined within the context of a type. They are declared in an `impl` block:
   ```rust
   impl User {
       fn name(&self) -> &str {
           &self.name
       }
   }
   ```

2 The `&self` parameter is a reference to the instance the method is called on. It is shorthand for `self: &Self`.

3 Methods can take `self` (ownership), `&self` (immutable borrow), or `&mut self` (mutable borrow):
   ```rust
   impl User {
       fn consume(self) -> String { self.name }       // takes ownership
       fn inspect(&self) -> u32 { self.age }           // borrows immutably
       fn birthday(&mut self) { self.age += 1; }       // borrows mutably
   }
   ```

4 `&self` is the most common. Use `&mut self` when the method modifies the instance. Use `self` only when the method should consume the instance.

5 Associated functions are defined in `impl` blocks but do not take `self`. They are called with the type name:
   ```rust
   impl User {
       fn new(name: &str) -> User {
           User {
               name: String::from(name),
               age: 0,
               active: true,
           }
       }
   }

   let user = User::new("Eve");
   ```

6 The `new` function is a Rust convention for constructors. It is not a keyword — just an associated function named `new`.

7 You can have multiple `impl` blocks for the same type. This is useful for organizing methods:
   ```rust
   impl User {
       fn new(name: &str) -> User { /* ... */ }
   }

   impl User {
       fn name(&self) -> &str { &self.name }
   }
   ```

8 Methods can return `Self` to enable method chaining:
   ```rust
   impl User {
       fn with_age(mut self, age: u32) -> Self {
           self.age = age;
           self
       }
   }

   let user = User::new("Frank").with_age(40);
   ```

9 Rust has no `this` keyword. `self` is the explicit name for the current instance, always passed as the first parameter.

## Chapter 3: Enums

1 An enum is a type that can be one of several variants. Each variant can hold different types of data:
   ```rust
   enum Message {
       Quit,
       Move { x: i32, y: i32 },
       Write(String),
       ChangeColor(i32, i32, i32),
   }
   ```

2 The `Quit` variant has no data. `Move` has named fields like a struct. `Write` has a single unnamed field. `ChangeColor` has three.

3 Enums can also have unit variants (no data) and tuple-like variants (ordered fields):
   ```rust
   enum Shape {
       Circle(f64),            // tuple variant
       Rectangle(f64, f64),    // tuple variant
       Triangle { base: f64, height: f64 }, // struct variant
   }
   ```

4 Construct enum values by specifying the variant:
   ```rust
   let msg = Message::Write(String::from("hello"));
   let shape = Shape::Circle(5.0);
   ```

5 Enums with data are stored on the stack if small, or heap-allocated internally if large. The size of an enum is the size of its largest variant plus a discriminant.

6 The `Option<T>` enum is built into Rust and represents a value that may or may not exist:
   ```rust
   enum Option<T> {
       Some(T),
       None,
   }
   ```

7 `Option<T>` is used instead of null. There is no `null` in Rust. Every value has a type and every type has a value.

8 The `Result<T, E>` enum represents either success or failure:
   ```rust
   enum Result<T, E> {
       Ok(T),
       Err(E),
   }
   ```

9 Use `Some` and `None` to construct `Option` values:
   ```rust
   let some_number: Option<i32> = Some(5);
   let no_number: Option<i32> = None;
   ```

10 Enums are the foundation of many Rust patterns. They are more powerful than enums in most other languages because they can carry data.

## Chapter 4: Pattern Matching

1 The `match` expression compares a value against a series of patterns and executes the code of the matching arm:
   ```rust
   enum Coin {
       Penny,
       Nickel,
       Dime,
       Quarter,
   }

   fn value_in_cents(coin: Coin) -> u8 {
       match coin {
           Coin::Penny => 1,
           Coin::Nickel => 5,
           Coin::Dime => 10,
           Coin::Quarter => 25,
       }
   }
   ```

2 Each arm must handle all possible variants. The compiler enforces exhaustiveness — you cannot forget a variant.

3 Use `_` as a catch-all pattern for variants you do not want to handle explicitly:
   ```rust
   fn describe(coin: Coin) -> &str {
       match coin {
           Coin::Penny => "a penny",
           _ => "something else",
       }
   }
   ```

4 Match can destructure enums with data:
   ```rust
   fn process(msg: Message) {
       match msg {
           Message::Quit => println!("Quitting"),
           Message::Move { x, y } => println!("Moving to ({x}, {y})"),
           Message::Write(text) => println!("Writing: {text}"),
           Message::ChangeColor(r, g, b) => println!("RGB: {r}, {g}, {b}"),
       }
   }
   ```

5 Match arms can bind values with `@`:
   ```rust
   fn describe_num(n: i32) -> &str {
       match n {
           x @ 1..=5 => "small positive",
           x @ 6..=10 => "medium positive",
           _ => "other",
       }
   }
   ```

6 `if let` is a shorthand for matching a single pattern. It is useful when you only care about one case:
   ```rust
   let config = Some(3u8);
   if let Some(max) = config {
       println!("Max is {max}");
   }
   ```

7 `let-else` (stabilized in Rust 1.65) runs a block when a pattern does not match and must diverge (return, break, or panic):
   ```rust
   let Some(max) = config else {
       println!("No config");
       return;
   };
   ```

8 `matches!` is a macro that returns `true` if a value matches a pattern:
   ```rust
   let x = 5;
   assert!(matches!(x, 1..=10));
   ```

9 Match is an expression, not a statement. It can return values and be assigned:
   ```rust
   let result = match coin {
       Coin::Penny => 1,
       Coin::Nickel => 5,
       Coin::Dime => 10,
       Coin::Quarter => 25,
   };
   ```

10 Patterns can be combined with `|` (or), ranges `..=`, and guards `if`:
   ```rust
   fn categorize(n: i32) -> &str {
       match n {
           1 | 2 | 3 => "low",
           x if x > 10 => "high",
           _ => "medium",
       }
   }
   ```

## Chapter 5: The Option Enum in Practice

1 `Option<T>` encodes the absence of a value. Instead of null, use `None`. Instead of a bare value, use `Some(value)`.

2 The `unwrap()` method extracts the value from `Some`, but panics on `None`:
   ```rust
   let x: Option<i32> = Some(5);
   assert_eq!(x.unwrap(), 5);
   ```

3 `expect()` is like `unwrap()` but takes a custom panic message:
   ```rust
   let x: Option<i32> = None;
   // x.expect("x should be Some"); // panics with the message
   ```

4 Prefer pattern matching or combinators over `unwrap()` in production code:
   ```rust
   let x: Option<i32> = Some(5);
   let doubled = x.map(|n| n * 2); // Some(10)
   ```

5 `Option` combinators let you chain operations without unwrapping:
   ```rust
   let x: Option<i32> = Some(5);
   let result = x
       .filter(|&n| n > 3)
       .map(|n| n * 2)
       .unwrap_or(0); // 10
   ```

6 `and_then` chains operations that return `Option`:
   ```rust
   fn find_even(n: i32) -> Option<i32> {
       if n % 2 == 0 { Some(n) } else { None }
   }

   let result = Some(4).and_then(find_even); // Some(4)
   let none_result = Some(3).and_then(find_even); // None
   ```

7 `or` and `or_else` provide fallbacks:
   ```rust
   let primary: Option<i32> = None;
   let fallback: Option<i32> = Some(42);
   let result = primary.or(fallback); // Some(42)
   ```

8 `unwrap_or` provides a default value:
   ```rust
   let x: Option<i32> = None;
   assert_eq!(x.unwrap_or(0), 0);
   ```

9 `unwrap_or_else` computes the default lazily:
   ```rust
   let x: Option<i32> = None;
   assert_eq!(x.unwrap_or_else(|| expensive_computation()), result);
   ```

10 `Option` is not just for errors. Use it any time a value may be absent: optional configuration, search results, missing map entries.

11 The `?` operator works with `Option` in functions that return `Option`:
   ```rust
   fn get_first(s: &str) -> Option<char> {
       s.chars().next()
   }

   fn get_second(s: &str) -> Option<char> {
       let first = get_first(s)?;
       let second = s.chars().nth(1)?;
       Some(second)
   }
   ```

12 When `?` encounters `None`, the function returns `None`. When it encounters `Some(x)`, it unwraps and continues with `x`.
