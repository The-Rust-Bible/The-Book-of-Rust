# Book of Joshua

*Rust topic: Traits, Generics, Trait Bounds, and Impl Blocks*

## Chapter 1: Defining and Implementing Traits

1 A trait defines a set of methods that a type must implement. It is a contract:
   ```rust
   trait Summary {
       fn summarize(&self) -> String;
   }
   ```

2 Implement a trait for a type with `impl TraitName for TypeName`:
   ```rust
   struct Article {
       headline: String,
       author: String,
   }

   impl Summary for Article {
       fn summarize(&self) -> String {
           format!("{} by {}", self.headline, self.author)
       }
   }
   ```

3 The `impl` block for a trait must define every method in the trait. The compiler enforces this.

4 Call trait methods on a type that implements the trait:
   ```rust
   let article = Article {
       headline: String::from("Rust is great"),
       author: String::from("Graydon"),
   };
   println!("{}", article.summarize());
   ```

5 A type can implement multiple traits. Each implementation goes in its own `impl` block:
   ```rust
   trait Display {
       fn text(&self) -> String;
   }

   impl Display for Article {
       fn text(&self) -> String {
           self.headline.clone()
       }
   }
   ```

6 You can implement a trait for a type that already exists, including types from the standard library, as long as either the trait or the type is defined in your crate. This is the orphan rule:
   ```rust
   // You cannot impl Display (from std) for Vec<T> (from std)
   // because neither is in your crate.
   ```

7 The orphan rule prevents conflicting implementations across crates. It ensures coherence — there is at most one implementation of a trait for a type.

8 Trait methods can be called on trait objects and generic parameters with trait bounds, not just concrete types.

## Chapter 2: Trait Bounds and Generic Functions

1 Generics let you write functions and types that work with multiple types. The syntax uses angle brackets:
   ```rust
   fn largest<T>(list: &[T]) -> &T
   where
       T: PartialOrd,
   {
       let mut largest = &list[0];
       for item in list {
           if item > largest {
               largest = item;
           }
       }
       largest
   }
   ```

2 The `<T>` after the function name declares a generic type parameter. `T` is a placeholder for any type.

3 Trait bounds restrict what types `T` can be. `T: PartialOrd` means `T` must implement the `PartialOrd` trait, enabling comparison with `>`.

4 The `where` clause is an alternative syntax for trait bounds. Use it when bounds are complex:
   ```rust
   fn process<T, U>(t: T, u: U) -> String
   where
       T: Display + Clone,
       U: Clone + Debug,
   {
       format!("{t} and {u:?}")
   }
   ```

5 Multiple trait bounds use `+`: `T: Display + Clone` means `T` must implement both `Display` and `Clone`.

6 Clearer trait bounds with `where` clauses improve readability, especially for functions with multiple generic parameters.

7 Trait bounds can be applied to structs and enums, not just functions:
   ```rust
   struct Pair<T> {
       x: T,
       y: T,
   }

   impl<T: Display + PartialOrd> Pair<T> {
       fn cmp_display(&self) {
           if self.x >= self.y {
               println!("x is larger: {}", self.x);
           } else {
               println!("y is larger: {}", self.y);
           }
       }
   }
   ```

8 Conditional implementations: you can implement methods for a generic type only when its type parameter satisfies certain bounds:
   ```rust
   impl<T: Display + PartialOrd> Pair<T> {
       fn cmp_display(&self) { /* only available when T: Display + PartialOrd */ }
   }
   ```

9 Blanket implementations implement a trait for any type that satisfies a condition. This is powerful but can cause coherence issues:
   ```rust
   impl<T: Display> ToString for T {
       fn to_string(&self) -> String {
           // uses T's Display implementation
           format!("{}", self)
       }
   }
   ```
   The standard library does this for `ToString` — any type that implements `Display` automatically gets `ToString`.

10 Generic code is monomorphized at compile time: the compiler generates a specialized version of the function for each concrete type used. This means zero runtime cost — generics are as fast as writing separate functions.

## Chapter 3: Default Implementations and Trait Inheritance

1 Traits can provide default method bodies. Types that implement the trait get these methods for free:
   ```rust
   trait Summary {
       fn summarize(&self) -> String;

       fn preview(&self) -> String {
           format!("Read more: {}", self.summarize())
       }
   }
   ```

2 When implementing the trait, you only need to define `summarize`. `preview` is inherited with its default body:
   ```rust
   impl Summary for Article {
       fn summarize(&self) -> String {
           format!("{} by {}", self.headline, self.author)
       }
       // preview is not defined here — uses the default
   }
   ```

3 Types can override default methods by providing their own implementation:
   ```rust
   impl Summary for Tweet {
       fn summarize(&self) -> String {
           format!("{}: {}", self.username, self.content)
       }

       fn preview(&self) -> String {
           String::from("Custom preview")
       }
   }
   ```

4 Traits can require other traits as supertraits. A type that implements the sub-trait must also implement all supertraits:
   ```rust
   trait Outline: Display {
       fn outline(&self) -> String;
   }

   impl Outline for Article {
       fn outline(&self) -> String {
           format!("Article outline: {}", self.text()) // uses Display's method
       }
   }
   ```

5 `Outline: Display` means: to implement `Outline`, you must also implement `Display`. Inside the `Outline` impl, you can call `Display` methods.

6 Supertraits create a hierarchy. For example, `Iterator: IntoIterator` in the standard library — every iterator is also an `IntoIterator`.

7 Traits can have associated types — types determined by the implementing type:
   ```rust
   trait Container {
       type Item;
       fn get(&self, index: usize) -> Option<&Self::Item>;
   }

   impl Container for Vec<i32> {
       type Item = i32;
       fn get(&self, index: usize) -> Option<&i32> {
           self.get(index)
       }
   }
   ```

8 Associated types are like generics, but there is only one per implementation. The implementing type decides what the associated type is.

9 Default implementations and supertraits let you build rich trait hierarchies with shared behavior, reducing code duplication.

## Chapter 4: Trait Objects and Dynamic Dispatch

1 Generic functions use static dispatch: the compiler generates specialized code for each type at compile time. This is fast but increases binary size.

2 When you need a collection of different types that share a trait, use trait objects with `dyn`:
   ```rust
   let summaries: Vec<Box<dyn Summary>> = vec![
       Box::new(article),
       Box::new(tweet),
   ];

   for item in &summaries {
       println!("{}", item.summarize());
   }
   ```

3 `dyn Summary` is a trait object — a pointer to a value that implements `Summary`. The concrete type is known only at runtime.

4 Trait objects use dynamic dispatch: the method to call is determined at runtime via a vtable (virtual method table). This has a small overhead compared to static dispatch.

5 `dyn` is required when using trait objects. Bare `Trait` names in this position are deprecated. Always write `dyn Trait` for clarity.

6 Trait objects must be behind a pointer: `&dyn Trait`, `Box<dyn Trait>`, `Rc<dyn Trait>`, or `Arc<dyn Trait>`. The pointer provides the size and location.

7 Not all traits can be used as trait objects. A trait is object-safe (dyn-compatible) if:
   - All methods are object-safe: no generic type parameters, no `Self` return type, no `Self` by value (except when `Self: Sized`).
   - The trait does not require `Self: Sized` as a supertrait.

8 `Clone` is not object-safe because it returns `Self` by value. You cannot have `Box<dyn Clone>`.

9 Static dispatch (`impl Trait` or generics) is preferred when possible: it is faster and allows inlining. Use dynamic dispatch (`dyn Trait`) when you need a heterogeneous collection or runtime polymorphism.

10 You can use `impl Trait` in function parameters as shorthand for generics with trait bounds:
   ```rust
   fn notify(item: &impl Summary) {
       println!("Breaking news! {}", item.summarize());
   }
   ```
   This is equivalent to `fn notify<T: Summary>(item: &T)`.

11 `impl Trait` in return position lets you return a type that implements a trait without naming the concrete type:
   ```rust
   fn make_summarizable() -> impl Summary {
       Article {
           headline: String::from("Return impl Trait"),
           author: String::from("Rust"),
       }
   }
   ```

## Chapter 5: Essential Standard Library Traits

1 `Debug` enables `{:?}` formatting. Derive it with `#[derive(Debug)]`:
   ```rust
   #[derive(Debug)]
   struct Point { x: i32, y: i32 }
   ```

2 `Display` enables `{}` formatting. Implement it manually for user-facing output:
   ```rust
   impl std::fmt::Display for Point {
       fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
           write!(f, "({}, {})", self.x, self.y)
       }
   }
   ```

3 `Clone` enables `.clone()` for explicit deep copies. Derive it with `#[derive(Clone)]`:
   ```rust
   #[derive(Clone)]
   struct User { name: String, age: u32 }
   ```

4 `Copy` is a marker trait for types that can be duplicated by copying bits (no heap allocation). Derive it only for small types where cloning is cheap:
   ```rust
   #[derive(Clone, Copy)]
   struct Point { x: i32, y: i32 }
   ```
   `Copy` requires `Clone`. A type that is `Copy` is always `Clone`.

5 `From<T>` enables `.into()` conversions. Implement `From` and get `Into` for free:
   ```rust
   struct Millimeters(u64);

   impl From<u64> for Millimeters {
       fn from(value: u64) -> Self {
           Millimeters(value)
       }
   }

   let mm = Millimeters::from(100);
   let mm: Millimeters = 100u64.into();
   ```

6 `TryFrom<T>` is like `From` but fallible, returning `Result<Self, Error>`:
   ```rust
   impl TryFrom<i64> for Millimeters {
       type Error = String;
       fn try_from(value: i64) -> Result<Self, Self::Error> {
           if value < 0 {
               Err("negative length".to_string())
           } else {
               Ok(Millimeters(value as u64))
           }
       }
   }
   ```

7 `Default` provides a default value for a type. Derive it or implement it:
   ```rust
   #[derive(Default)]
   struct Config { timeout: u32, retries: u8 }
   ```

8 `PartialEq` and `Eq` enable `==`. Derive `PartialEq` for most types, `Eq` for types without floating-point fields:
   ```rust
   #[derive(PartialEq)]
   struct Version { major: u32, minor: u32 }
   ```

9 `PartialOrd` and `Ord` enable comparison operators. Derive for types with natural ordering:
   ```rust
   #[derive(PartialEq, PartialOrd)]
   struct Version { major: u32, minor: u32 }
   ```

10 `Hash` enables use as a `HashMap` key. Derive alongside `Eq`:
   ```rust
   #[derive(Hash, Eq, PartialEq)]
   struct UserId(u64);
   ```

11 `Iterator` is the core of Rust's functional style. Implement `next()` to make a type iterable:
   ```rust
   struct Counter { count: u32 }

   impl Iterator for Counter {
       type Item = u32;
       fn next(&mut self) -> Option<u32> {
           if self.count < 5 {
               self.count += 1;
               Some(self.count)
           } else {
               None
           }
       }
   }
   ```

12 `Drop` runs cleanup code when a value goes out of scope:
   ```rust
   struct Resource { id: u32 }

   impl Drop for Resource {
       fn drop(&mut self) {
           println!("Releasing resource {}", self.id);
       }
   }
   ```

13 Deriving traits is the idiomatic approach. Derive everything you can, and implement manually only when you need custom behavior. Common derive combinations:
   - `#[derive(Debug, Clone, PartialEq)]` — most common
   - `#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]` — for value types used as map keys
   - `#[derive(Default)]` — for configuration structs
