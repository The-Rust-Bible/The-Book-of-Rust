# Book of Ruth

*Rust topic: Modules, Packages, Crates, and Use Paths*

## Chapter 1: Modules and Visibility

1 A module organizes code into namespaces. Declare a module with `mod`:
   ```rust
   mod garden {
       pub fn plant() {
           println!("Planting seeds");
       }
   }
   ```

2 Items inside a module are private by default. Use `pub` to make them public:
   ```rust
   mod garden {
       pub fn plant() {}          // public
       fn water() {}              // private
   }
   ```

3 Access module items with `::`:
   ```rust
   garden::plant(); // OK — plant is pub
   // garden::water(); // error — water is private
   ```

4 Modules can be nested:
   ```rust
   mod garden {
       pub mod vegetables {
           pub fn carrot() {}
       }
       pub mod fruits {
           pub fn apple() {}
       }
   }
   garden::vegetables::carrot();
   garden::fruits::apple();
   ```

5 Modules can hold structs, enums, functions, traits, constants, and other modules:
   ```rust
   mod config {
       pub struct Settings {
           pub timeout: u32,
       }

       pub const VERSION: &str = "1.0.0";

       pub fn load() -> Settings {
           Settings { timeout: 30 }
       }
   }
   ```

6 `pub(crate)` makes an item visible within the current crate but not outside:
   ```rust
   mod internal {
       pub(crate) fn helper() {} // visible anywhere in this crate
   }
   ```

7 `pub(super)` makes an item visible in the parent module:
   ```rust
   mod parent {
       mod child {
           pub(super) fn helper() {} // visible in parent module
       }
   }
   ```

7 `pub(in path)` makes an item visible within a specific ancestor module:
   ```rust
   mod a {
       mod b {
           mod c {
               pub(in crate::a) fn helper() {} // visible in crate::a and descendants
           }
       }
   }
   ```

8 Struct fields can be `pub` independently. A struct can be public while its fields remain private:
   ```rust
   mod data {
       pub struct Point {
           pub x: i32,  // public field
           y: i32,      // private field
       }
   }
   ```

9 Enum variants inherit the visibility of the enum. If the enum is `pub`, all its variants are `pub`:
   ```rust
   mod colors {
       pub enum Color {
           Red,
           Green,
           Blue,
       }
   }
   // All variants are accessible: colors::Color::Red
   ```

## Chapter 2: Paths and the Use Keyword

1 Paths start from one of three places: the crate root, the current module, or an external crate.

2 `crate::` refers to the crate root — the top level of your project:
   ```rust
   mod a {
       pub fn hello() {}
   }

   fn main() {
       crate::a::hello();
   }
   ```

3 `self::` refers to the current module:
   ```rust
   mod utils {
       pub fn helper() {}

       pub fn caller() {
           self::helper();
       }
   }
   ```

4 `super::` refers to the parent module:
   ```rust
   mod outer {
       pub fn parent_fn() {}

       mod inner {
           fn child_fn() {
               super::parent_fn(); // calls parent
           }
       }
   }
   ```

5 The `use` keyword brings paths into scope, shortening long paths:
   ```rust
   mod garden {
       pub mod vegetables {
           pub fn carrot() {}
       }
   }

   use garden::vegetables::carrot;

   fn main() {
       carrot(); // instead of garden::vegetables::carrot()
   }
   ```

6 `use` can bring in multiple items with `::{}`:
   ```rust
   use std::collections::{HashMap, HashSet};
   use std::io::{self, Read, Write};
   ```

7 `use` can rename items with `as`:
   ```rust
   use std::collections::HashMap as Map;
   ```

8 `use` can glob-import everything from a module with `*`:
   ```rust
   use std::collections::*;
   // Brings HashMap, HashSet, BTreeMap, etc. into scope
   ```
   Avoid glob imports in production code — they make it unclear where names come from.

9 `use` creates aliases, not copies. The original path is still valid:
   ```rust
   use std::collections::HashMap;
   let a: HashMap<String, i32> = HashMap::new();
   let b: std::collections::HashMap<String, i32> = std::collections::HashMap::new();
   ```

10 By convention, `use` statements go at the top of the file, grouped by source: standard library first, then external crates, then crate-local.

11 `pub use` re-exports an item. This lets other modules access it through your module:
   ```rust
   mod utils {
       pub fn helper() {}
   }

   mod api {
       pub use crate::utils::helper; // re-export
   }

   fn main() {
       api::helper(); // accessible via api module
   }
   ```

12 Re-exporting is how crates expose their API. A crate's `lib.rs` typically re-exports the items users need:
   ```rust
   // lib.rs
   pub mod config;
   pub mod parser;
   pub use parser::parse;
   pub use config::Settings;
   ```

## Chapter 3: Packages and Crates

1 A package is a Cargo project with a `Cargo.toml` file. It contains one or more crates.

2 A crate is a compilation unit: either a binary crate (`src/main.rs`) or a library crate (`src/lib.rs`).

3 A package can contain both a library and a binary:
   ```text
   my_package/
   ├── Cargo.toml
   └── src/
       ├── lib.rs       ← library crate
       └── main.rs      ← binary crate (uses the library)
   ```

4 The binary crate can use the library crate by importing it:
   ```rust
   // src/main.rs
   use my_package::add;

   fn main() {
       println!("{}", add(2, 3));
   }
   ```

5 The library crate defines public items that the binary can use:
   ```rust
   // src/lib.rs
   pub fn add(a: i32, b: i32) -> i32 {
       a + b
   }
   ```

6 Create a new library package with `cargo new --lib my_lib`. Create a binary with `cargo new my_bin` (the default).

7 The `Cargo.toml` file defines the package. The `[package]` section has metadata:
   ```toml
   [package]
   name = "my_package"
   version = "0.1.0"
   edition = "2024"
   description = "A short description"
   license = "MIT"
   ```

8 The `edition` field specifies which Rust edition to use. Use `"2024"` for new projects.

9 The `[dependencies]` section lists external crates:
   ```toml
   [dependencies]
   serde = { version = "1.0", features = ["derive"] }
   tokio = { version = "1", features = ["full"] }
   ```

10 The `[dev-dependencies]` section lists crates only needed for tests and examples:
   ```toml
   [dev-dependencies]
   criterion = "0.5"
   ```

11 The `[build-dependencies]` section lists crates needed by build scripts (`build.rs`):
   ```toml
   [build-dependencies]
   cc = "1.0"
   ```

12 Crates from crates.io are downloaded and cached in `~/.cargo/registry/`. They are compiled once and reused across projects.

## Chapter 4: Module Organization Patterns

1 Inline modules are defined in the same file with `mod name { ... }`. Use them for small, related items:
   ```rust
   mod math {
       pub fn add(a: i32, b: i32) -> i32 { a + b }
       pub fn sub(a: i32, b: i32) -> i32 { a - b }
   }
   ```

2 Out-of-line modules are defined in separate files. Declare the module in the parent:
   ```rust
   // src/main.rs
   mod math; // looks for src/math.rs
   ```

   ```rust
   // src/math.rs
   pub fn add(a: i32, b: i32) -> i32 { a + b }
   pub fn sub(a: i32, b: i32) -> i32 { a - b }
   ```

3 Modules with submodules use a directory:
   ```text
   src/
   ├── main.rs
   └── math/
       ├── mod.rs      ← or src/math.rs with src/math/ dir
       ├── algebra.rs
       └── calculus.rs
   ```

   ```rust
   // src/math/mod.rs
   pub mod algebra;
   pub mod calculus;
   ```

   ```rust
   // src/math/algebra.rs
   pub fn add(a: i32, b: i32) -> i32 { a + b }
   ```

4 The modern pattern (Rust 2018+) prefers `src/math.rs` with a `src/math/` directory for submodules, rather than `mod.rs`:
   ```text
   src/
   ├── main.rs
   ├── math.rs          ← declares pub mod algebra; pub mod calculus;
   └── math/
       ├── algebra.rs
       └── calculus.rs
   ```

5 A common library structure:
   ```text
   src/
   ├── lib.rs           ← pub mod declarations and re-exports
   ├── config.rs        ← configuration types
   ├── error.rs         ← error types
   ├── parser.rs        ← parsing logic
   └── parser/
       ├── mod.rs       ← parser submodule declarations
       ├── lexer.rs     ← lexer
       └── ast.rs       ← AST types
   ```

6 Use `pub use` in `lib.rs` to create a clean public API:
   ```rust
   // lib.rs
   mod config;
   mod error;
   mod parser;

   pub use config::Config;
   pub use error::ParseError;
   pub use parser::parse;
   ```

   Users can then write `use my_crate::{Config, ParseError, parse};` without knowing the internal module layout.

7 Circular module dependencies are not allowed in Rust. If two modules seem to need each other, they probably belong in the same module or a shared parent.

8 Module privacy follows the principle of least privilege: make everything private by default, and only `pub` what needs to be shared.

9 The `#[path = "..."]` attribute lets you specify a custom file path for a module:
   ```rust
   #[path = "custom_location.rs"]
   mod my_module;
   ```

10 Modules are compile-time constructs. They have zero runtime cost — the compiler inlines everything during compilation.
